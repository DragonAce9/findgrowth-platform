## 3. Предложения по экранам

Сквозные правила для всех макетов:

1. Слово **«эффект»** — только при `status === "confirmed"`. Иначе «наблюдаемая разница». Это уже в `liftParagraph`, остаётся довести до визуала.
2. Интервал всегда рядом с точкой, одним форматом: `50 % (39 %–61 %)` — пробел перед %, один десятичный только там, где он есть в данных. Один форматтер на все экраны.
3. Три состояния доказательности **одним визуальным языком**: `enough` — обычный вид; `thin` — `.tag` «мало данных» + причина из `evidenceState`; `hidden` — столбца нет, вместо него серая заглушка «меньше пяти человек».
4. Английские идентификаторы (`received_email`, `Placed Order`, `hero-cta`, `mobile`) — в `<code>`-начертании, с русской подписью рядом. Так читатель понимает, что это имя столбца/объекта, а не текст.

### 3.1 Неделя (`src/app/page.tsx`)

#### P0 — Статус холдаута как вердикт, не как заголовок

Сейчас (срез 2):

```
Наблюдаемая разница между группами
Письмо получают 10, без письма остаются 10. Разница повтора 20% (-20.6%–52.8%).
Вероятность, что письмо дало повтор чаще: 80.3%. Это вероятность, не доля людей.
Оценка замороженной выручки: 144 €. …
Сезонная поправка недоступна: нет той же когорты годом ранее.
```

Предложение — тот же `.section`, но с тремя визуальными состояниями на `.verdict`:

```
┌──────────────────────────────────────────────────────────────────────┐
```

## 5. Что намеренно не показываем и почему

| Не показываем | Почему |
|---|---|
| `predicted_lift`, прогноз выручки от письма | Платформа измеряет, а не обещает. На экране только наблюдаемая разница с интервалом и «замороженная выручка» как арифметика (люди × повтор × чек), подписанная «не прогноз» |
| Слово «эффект» без подтверждённого холдаута | `liftParagraph` называет эффектом только `confirmed`. Визуальный статус (раздел 3.1) делает это правило видимым |
| Точечные оценки без интервала | Везде, где есть доля или среднее, рядом интервал. Где интервала посчитать нельзя — состояние «мало данных», а не голое число |
| Адреса, телефоны, имена, выгрузка списков | Платформа отдаёт только хеши ключей и условие сегмента (Placed Order); «Нельзя» в блоке Закон. Списки «Кому» предлагаем сворачивать, не убирать |
| Отправку писем, коннекторы к Klaviyo | Платформа не отправляет; ТЗ — поручение человеку. Кнопок «отправить» нет и не будет |
| Цифры 91 % / 24 % и подобные «отраслевые» бенчмарки | Не из файла бренда — не на экране |
| SaaS-LTV = ARPU ÷ churn | Карточки прямо говорят «Не ARPU ÷ отток». Показываем только когортный LTV по прожитому горизонту |
| Группы меньше порога (`hidden`) | Меньше пяти человек идентифицирует людей и даёт случайные доли. Заглушка с причиной вместо столбца |
| Сырой score модели | Бренду — ведро словами; оператору — метрики качества. Само число 0–1 ничего не решает и провоцирует ранжирование людей |
| Co-view как основу рекомендации | Основа — популярное в категории; персональная пара — исключение при подтверждённой нижней границе. Так и пишем |
| 365-дневный LTV, когда никто не прожил год | Карточка остаётся на месте в состоянии «скрыто» с причиной — чтобы было видно, что это не забыли, а не досчитали |
| Новые UI-библиотеки | Все макеты собираются из `globals.css` и `week-charts.tsx`; единственный новый компонент — `StepChart` на уже существующем `plotFrame` |

## 6. Найденные UX-дефекты (сводно)

Вёрстка и состояния:

1. Верхняя навигация на ширине ~897 px: «АККАУНТ» обрезан, «Срез 1 сентября 2026» наезжает на «Студия», «Каталог / Выйти» переносятся второй строкой (все скриншоты).
2. `textarea` моноширинный — нет в правиле `button, input, select { font: inherit }` (`globals.css`; скриншот 03).
3. «Кому» на косметике — стена из ~570 идентификаторов без свёртки, при том что ход — сайт и письмо запрещено (скриншот 10).
4. Карточка `.kpi` «0 € / Обрыв сайта, 80 человек» читается как сломанная (скриншот 02).
5. Измеренная разница на Брифе — 12-px `.source` (скриншот 08).
6. Когортный LTV — три строки `.source`, 365 дней исчезает без причины (скриншот 03c).
7. Next dev-оверлей «1 Issue» появлялся на срезе 2 и косметике — дев-инструмент, не продуктовый дефект, но стоит посмотреть консоль.

Противоречия в данных на экране:

8. Срез 1: Неделя и карточка ТЗ — «40 человек / control 40»; Бриф и списки ТЗ — «получают 10, остаются 10» (скриншоты 02b, 04b, 05).
9. Косметика, Бриф: при «письмо нельзя» показана карточка «Письмо получают 10 человек… Окно отправки: день 96–96…, пик хазарда — день 121»: окно нулевой ширины, пик вне окна, письмо запрещено (видно в снапшоте страницы над скриншотом 11).
10. Косметика, Неделя: «В control 284 человек… нужно 1483» под карточкой «Карточка товара: править сайт».

Текст и форматирование:

11. Английское на экране: `mobile / desktop / tablet`, `identity_coverage` и другие имена метрик Каталога, `hero-cta`, `Placed Order`, `received_email`, `control`, `flow`, `live / queue`.
12. Форматы чисел: «99.4 %» и «99.2%» в одной строке; «39,3» на столбце и «30.3–48.6» без % в подписи; «1250820 человек» и «1 250 820 не перешли» на одном экране; «55 (49–61)» без единицы (косметика).
13. ТЗ: фраза приёмки про `received_email` три раза, фраза мощности — два.
14. P&L: «Срез, не месяц.. Файл × оператор.» — двойная точка.
