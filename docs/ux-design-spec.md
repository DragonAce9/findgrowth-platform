## 1. Дизайн-принципы

Семь правил. Каждое — проверяемое на экране, не пожелание.

| # | Правило | Как проверить на экране |
|---|---|---|
| 1 | **Интервал всегда виден рядом с точкой.** Доля, разница, LTV, метрика модели — точка и интервал в одном зрительном блоке: усы на столбце, полоса на кривой, скобки в той же строке. Интервал в подписи, а точка на графике — нарушение | Закрыть подпись рукой: интервал всё равно виден? |
| 2 | **Статус никогда только цветом.** Любой цветной элемент несёт слово и маркер-символ. Бриф и ТЗ печатаются в ч/б — статус должен читаться без цвета | Напечатать в PDF (серый) — статус понятен? |
| 3 | **«Мало данных» — полноправное состояние, не пустота.** Карточка, столбец или строка на месте, с причиной словами. Исчезнувшая строка (как LTV 365 сейчас) — дефект | Сравнить число ожидаемых блоков с фактическим: все на месте? |
| 4 | **Один вывод на экран.** Первая карточка под заголовком — одно решение; всё остальное доказывает его. Графики не живут без заголовка-утверждения (`.proof h2`) | Прочитать только h1 и первую карточку: ясно, что делать в понедельник? |
| 5 | **Цифры только в цифровых блоках.** `.kpi .val`, подписи графиков, строки аудитории — с числами. Проза карточек проблем, «Ведро», «Что донести» — без единой цифры (голден-тест `golden.test.ts:530`) | `grep /\d/` по этим строкам пуст? |
| 6 | **Русский везде.** Латиница допустима только как имя столбца/объекта в `<code>` с русской подписью рядом | Лексический тест F6.3 зелёный? |
| 7 | **Дефект данных вскрывается, а не маскируется.** Если движок даёт противоречивые числа, экран говорит об этом плашкой с причиной (паттерн «честная плашка», §4.6) | Нет ли на экране двух разных чисел об одном и том же без объяснения? |

Иерархия внимания владельца бренда на любом экране: **статус → решение → число с интервалом → доказательство → приложение.** Всё, что оператору, а не бренду, свёрнуто в `details.week-slice`.

### 2.3 Цветовые роли статусов: цвет + маркер + слово

Каждый статус — тройка. Маркер — символ Unicode в том же `<span>`, перед словом, без отдельного шрифта. При печати и в ч/б остаются маркер и слово.

**Группа А. Холдаут** (`HoldoutState`, компонент `HoldoutVerdict`, §3.1)

| Состояние | Слово | Маркер | Фон блока | Цвет слова | Классы |
|---|---|---|---|---|---|
| `confirmed` | Подтверждён | ✓ (U+2713) | `--sage-soft` | `--sage-ink` | `.verdict.ok` + `.status.ok` |
| `unchecked` | Не проверен | ○ (U+25CB) | `--gold-soft` | `--gold-ink` | `.verdict.wait` + `.status.wait` (новые) |
| `violated` | Нарушен | ✕ (U+2715) | `--danger-soft` | `--danger-ink` | `.verdict.bad` + `.status.bad` (новые) |

**Группа Б. Доказательность** (`evidenceState`, компонент `EvidenceBadge`, §3.3)

| Уровень | Слово | Маркер | Фон чипа | Цвет слова | Класс |
|---|---|---|---|---|---|
| `enough` | — (ничего не рендерится) | — | — | — | — |
| `thin` | мало данных | ◐ (U+25D0) | `--gold-soft` | `--gold-ink` | `.tag.thin` |
| `hidden` | скрыто | ▧ (U+25A7) | `--paper-2` | `--ink-soft` | `.tag.hidden`; на графике — штрихованная заглушка `HiddenStub` |

**Группа В. Решение по ходу** (`moveDecision`, компонент `AccumulationScale`, §3.6)

| Решение | Слово (`MOVE_DECISION_RU`) | Маркер | Фон зоны шкалы | Цвет слова |
|---|---|---|---|---|
| `scale` | масштабировать | ↑ (U+2191) | `--sage-soft` | `--sage-ink` |
| `continue` | продолжать | → (U+2192) | `--gold-soft` | `--gold-ink` |
| `stop` | остановить | ■ (U+25A0) | `--danger-soft` | `--danger-ink` |

**Группа Г. Готовность** (`PilotChecklist`, §3.9): «Готов» ✓ `.status.ok`; «Не готов» ✕ `.status.bad`. Строки чек-листа: ✓ в `--sage-ink`, ✗ (U+2717) в `--danger-ink`, у желательного пункта ✓/✗ в `--muted`.

**Группа Д. Модель** (`ModelCard`, §3.7): «тень» ○ нейтральный чип (`--paper-2` / `--ink-soft`); «претендент» → `.tag` (gold); «чемпион» ✓ `.status.ok`.

Новый класс `.status` (чип статуса): геометрия `.tag` (`inline-flex; padding 3px 8px; border-radius 4px; letter-spacing 0.04em; text-transform uppercase; font-weight 700`), но **12 px**, с маркером через обычный пробел. Отличие от `.tag`: `.tag` — метка контекста («Демо данные», «Ход 1 · понедельник»), `.status` — вердикт. `→ §9, п. 3` (в требованиях `.verdict.ok/.bad` используется и как блок, и как чип).

Почему не `.verdict.no` для «нарушен»: `.verdict.no` в коде — это `--gold-soft` и занят под «Письмо нельзя» (§3.1 требований). Не трогаем.

## 3. Спецификация компонентов

Общее для всех двенадцати:
- Серверные компоненты, кроме `KeyList`. Стили — только классы `globals.css` (существующие + §10). Иконки — символы Unicode или инлайн-SVG.
- Состояние «загрузка» для серверных компонентов не рисуется (страница рендерится целиком). Состояние «ошибка данных» — паттерн «честная плашка» (§4.6), не пустое место.
- Каждый SVG: `role="img"`, `<title>`, `aria-label` с ключевыми числами; текстовая альтернатива — та же фраза, что в `.source` под графиком.
- На узком экране (≤ 860) все сетки — одна колонка; SVG не сжимается ниже 720 единиц, а прокручивается (§5.3).

**Назначение.** Показать, задевает ли интервал разницы ноль, не читая чисел. Живёт только внутри `HoldoutVerdict`.

**Анатомия** (единицы viewBox; `W = 880`, высота **72**, `→ §9, п. 4`: в требованиях «~60», 72 нужны для двух рядов подписей):

### 4.6 Паттерн «честная плашка» — как показывать вскрытый дефект данных

Используется, когда экран знает, что числа противоречат друг другу или часть расчёта отсутствует (F0.1/F0.2 до исправления движка, DOR-задачи F3.3, F4.1, F4.3, F4.6, кривая без движка в F3.2).

```
┌─ .note.warn ───────────────────────────────────────────────────────────────┐ padding 12 14, --gold-soft
│ ⚠ В снимок попали 20 из 40 человек сегмента.                     ← что видно │ strong 14 px, маркер ⚠ (U+26A0)
│ Снимок строится из первых двадцати покупателей, а не из сегмента  ← почему   │ 14 px --ink-soft
│ хода. Списки «Кому / Кому не» — именно эти 20. Исправление — на   ← что это  │
│ стороне движка.                                                    значит   │
└────────────────────────────────────────────────────────────────────────────┘
```

Правила плашки:
1. Три части, всегда в этом порядке: **что видно** (с числами), **почему** (одна фраза), **что это значит для решения** (одна фраза). Без идентификаторов задач на экране — «F0.2» только в коде и доках.
2. Стоит **рядом с числом, которое под вопросом** (в карточке хода — под строкой аудитории), не внизу страницы.
3. Не заменяет числа: оба числа остаются видны. Запрещено «выбрать одно» или спрятать второе.
4. Исчезает сама, когда условие расхождения перестаёт выполняться (`snapshot.length === segment.size`).
5. Не используется для нормальных состояний «мало данных» — у них свой чип (§3.3).

### 5.3 Графики на узком экране

### 6.2 Правила формулировок

| Ситуация | Пишем | Не пишем |
|---|---|---|
| Холдаут `confirmed` | «измеренный эффект», «письмо дало повтор чаще» | — |
| Холдаут `unchecked` | «наблюдаемая разница между группами», «разница повтора» | «эффект», «лифт», «письмо дало» |
| Холдаут `violated` | «холдаут нарушен», «группы разошлись», чисел нет | любые числа разницы |
| Интервал словами | «50 % (39,3 %–60,7 %)»; в прозе — «от 39 до 61 %» допустимо один раз в абзаце для чтения вслух | «±11 %», «около 50 %», «примерно» |
| Интервал через ноль | «Интервал задевает ноль: разница могла быть и в другую сторону» | «не значимо», «p > 0,05», «статистически незначимо» |
| Вероятность | «Вероятность, что письмо дало повтор чаще: 80,3 %. Это вероятность, не доля людей» | «шанс 80 %», «уверенность 80 %» |
| «Мало данных» | чип + причина из `evidenceState`: «мало данных для сравнения устройств»; в прозе — «Этого мало, чтобы …» + что именно нельзя сделать | «недостаточно данных» без продолжения, «n/a», «—» без причины |
| «Скрыто» | причина всегда: «меньше пяти человек», «ни один покупатель не прожил год» | пустая ячейка, пропуск строки |
| Деньги | «уже в кассе», «уже заплачено», «замороженная выручка … Не прогноз» | «потенциал», «upside», «прогноз выручки» |
| Решение | «Решение: продолжать» (слово из `MOVE_DECISION_RU`) | «рекомендуем», «стоит попробовать» |
| Модель | «модель подсказывает товар», «в тени», «ведро: давно не покупал» | «score 0,73», «вероятность возврата 73 %» для бренда |
| Приказы | инфинитив: «Писать тем, кто …», «Править карточку товара» | «Вам нужно», «Мы советуем» |
| Отрицательные состояния | факт + следующий шаг: «Второго среза нет. Сравнить … пока нечем» | «Ошибка», «Нет данных» |

Тон: короткие предложения, глагол в начале, без восклицаний, без «!» и без эмодзи. Числа всегда с единицей. Один абзац — одна мысль.
